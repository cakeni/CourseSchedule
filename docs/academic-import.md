# 高校教务导入：范围、安全边界与验证流程

## 入口与数据流

入口为「导入课程 → 从教务系统导入」。学校网页登录只负责建立学校自己的会话；读取结果仍统一进入：

`ParsedImport → ImportAnalyzer → 导入预览 → commitImport`

预览确认前不会写入课程数据库，也没有第二套提交逻辑。

## 当前支持层级

- 西南石油大学：内置金智 / Wisedu 入口，已由用户在真实账号下确认可导入；现有 `wdkb` 流程保持第一优先级。
- 山东财经大学：内置强智 + 学校 WebVPN 初始配置，仍标记为试用，需本校用户继续核对入口变化、校区和课表页面。
- 南京航空航天大学：本科使用教务处 `aao-eas` EAMS 入口，读取页面的 `window.table0 + unitCount`；研究生使用南软 `gmis5` 入口。两者均标记为试用，仍需本校账号真机核对。
- 学校目录：收录 3,566 条去重的学校 / 教务候选入口配置，可按“专科及本科 / 研究生 / 通用教务”筛选；这不是 3,566 所已适配学校。
- 目录状态分为“已验证 / 通用适配 / 实验识别 / 需填写网址 / 需专用适配”。叠加内置学校覆盖和 `ziyan` 独立入口复核后，2,682 条有本地入口和解析路线、可以直接尝试打开；另有 764 条已有本地解析路线但上游没有可直接加载的网址，可由用户填写学校官网确认的教务地址后试用；新增适配器按 WakeUp 的本地规则识别苏大、浙大、新大、法大、华农、哈工大、哈工深、协和天地、电子科大研究生及广二师等页面，`swjtu_post` 复用金智解析。剩余 120 条仍需要专用本地适配器或可靠入口。1,088 条 `ziyan` 记录中有 984 条改走设备端实验解析，104 条尚无可靠公网入口。应用不调用原服务的云端解析。当前真机已验证 1 所。

通用入口目前列出以下 24 个页面类型：

- 金智教务（jwapp / gsapp）、AIC 教务、URP 新版系统、URP 系统
- 为途教务、乘方教务、优慕课在线、凌展教务
- EAMS 教务、南软教务、奕联教务、强智教务、旧强智教务
- 拓扑教务、通用 HTML 课表、新树维教务、树维手机导入、树维教务、树维教务（简易导入）
- 新青果教学安排表、青果教务（正选结果导入）、正方教务
- 超星教务、超星分享课表导入

“出现在列表中”表示应用已有对应协议字段或严格 HTML 读取策略，**不表示同厂商的每个版本、每所学校都已登录验证**。
真实页面若更换接口、采用跨域 iframe、仅返回图片或不暴露完整学期数据，应用会拒绝或提示读取失败，不会猜测时间后部分导入。

## 已实现的本地解析形状

- 金智：保留西南石油已验证的 `wdkb` 读取，并依次尝试本科 `xkjglapp/xsjxrwcx.do`、研究生 `gsapp` 和移动端 `homeapp`；解析大写 `KCM / SKJS / JASMC / SKXQ / KSJC / JSJC / SKZC` 与移动端小写字段。
- EAMS：由独立解析器读取页面变量 `table0 + unitCount`，按星期/节次单元格还原课程并只合并相邻节次，不再复用树维逻辑。
- 正方：分为旧版 HTML 与新版 `jwglxt` JSON。只有页面同时提供明确学年、学期参数和同源端点时才发起页面内请求；已匹配但 JSON 字段不完整时不会回退到 HTML。
- 强智：注册 `qz / qz_2017 / qz_2024 / qz_br / qz_with_node / qz_crazy` 六种本地变体，分别识别传统表格、Element UI、tooltip 列表、换行与节点布局。
- 青果：`kingo_new` 与 `kg_zx` 使用专用报表解析，处理 rowspan/colspan 和同课多个时间段；图片课表明确拒绝。
- 南软：使用 `#kb / table.kb / .kb` 专用网格解析器，合并单元格仍必须给出明确周次。
- URP 新版：`dateList[].selectCourseList[].timeAndPlaceList[]`，以及 `kcm + id.skxq/skzc/skjc` 两种常见形状。
- 乘方：页面变量 `kbxx` 中的 `kcmc / xq / jcdm2 / zcs / jxcdmcs / teaxms`。
- 树维：包含 `activities`、`weekIndexes`、`weekday`、`startUnit/endUnit` 的当前结构；同时保留旧移动页单元格位图结构。
- 凌展：`kcmc / xqj / djj / qmz / dsz`，按该协议的 0=双周、1=单周、2=全部解释。
- 超星教务：`kckbData` 课程字段；超星分享：`lessonArray` 课程字段。
- AIC：`table#table`、`.courseInfo`、`.weekDetail`、`.teacher`、`.place`。
- 其他 HTML 类型：只接受能明确找到课程、星期、周次、节次（或开始 + 结束/持续节数）的表格或已知课表网格。

周次最终统一经过 `compressImportWeeks`：连续周可合并，完整单/双周可保留周类型，不连续周会拆成多条 `Course`；同一门课的多个星期或多个节次不会相互覆盖。

## 学校目录的操作方式

目录 schema v3 将上游 `sourceType`（来源事实）与本地 `adapterId`（解析实现）分开，并分别保存登录、认证和课表读取范围。v1/v2 目录仍可读取，加载时会映射到本地适配器。

1. 搜索并选择学校；有本地路线的条目会自动匹配教务协议和入口。标记为“需填写网址”的条目已经知道教务厂商，可填写从学校官网确认的教务地址后复用相应解析器；“通用教务”分类也使用同一流程。真正标记为“需专用适配”的条目只展示原因和反馈入口。
2. 在学校网页完成登录，按页面提示进入完整学期课表并等待加载。
3. CAS、SSO、WebVPN 和厂商登录产生的 HTTP/HTTPS 跨域跳转会直接留在导入 WebView 中；需要交给其他应用处理的特殊协议会先请求用户确认。
4. 点击「读取页面所选学期课表」，核对导入预览后再提交。
5. 未收录学校通过项目 Issue 提交学校名称和学校官方入口，由维护者审核后加入目录。

使用 WebVPN 时，目录仍应配置具体教务资源地址，方便「打开教务」按钮直达课表；登录过程中的跨域和代理跳转不受目录域名限制。

当前目录使用 WakeUp 6.1.20 在 2026-09-02 显示的公开学校名、入口和系统类型作为互操作事实，并用 MIT 许可的 `baoozak/timetable` 固定提交补充或替换部分可独立验证的入口。没有复制 WakeUp 实现代码、账号、Cookie 或课表响应；来源与声明随 APK 保存在 `academic_school_directory_NOTICE.txt`。目录记录仅表示“有候选入口和协议”，不等于已由本校账号验证。

## 安全边界

- 学校入口优先使用 HTTPS；目录中明确标记为 HTTP 的入口在打开前仍会提示明文风险。导入 WebView 不按学校域名过滤后续 HTTP/HTTPS 导航或重定向。
- `intent:`、自定义协议、`file:`、`content:` 等需要离开 WebView 的链接会先显示确认；Android 无法处理时只显示普通的链接错误。
- SSL 错误默认停止并显示证书警告；用户确认学校官方地址后可仅对该主机、本次导入继续，离开页面或结束导入后不会保留授权。
- 账号密码只进入学校网页；金智请求始终在页面同源 `fetch` 中完成。应用不保存表单、Cookie、localStorage、sessionStorage 或完整教务响应；树维 `print-data` 的已登记 GET 路径只在同一课表范围内临时重放 WebView 请求，Cookie 不进入解析结果、诊断或持久存储。
- 所有入口都不注册原生 `JavascriptInterface`。读取脚本通过页面内临时结果对象回传，只投影已知课程字段，并复制有限的可见课表标签；不复制表单、输入框、脚本、链接或资源地址。
- 读取数据有大小、节点数量、递归深度和课程数量边界。必要字段不完整时整次失败，避免静默漏课。

解析失败可先查看脱敏诊断，再由用户通过系统文件创建器手动保存 JSON。诊断只包含应用版本、目录 ID、系统/适配器、去查询参数的安全化路径、捕获方式、错误码、命中选择器、iframe 状态、表格行列结构以及 JSON 键/值类型；课程、姓名、教师、教室等自由文本会替换为稳定占位符，Cookie、token、ticket、表单、脚本和链接字段直接移除。应用不会自动上传诊断。

统一错误码为 `NO_TIMETABLE / UNSUPPORTED_VARIANT / MISSING_DAY / MISSING_SECTION / MISSING_WEEK / PARTIAL_PARSE / AMBIGUOUS_VARIANT / FRAME_BLOCKED / CAPTURE_MISS / PAYLOAD_TOO_LARGE / UNTRUSTED_SOURCE`。

## WakeUp APK 互操作核对

用户提供的 `base.apk` 已在隔离任务目录中做静态与本机运行时核对：包名 `com.suda.yzune.wakeupschedule`，版本 `6.1.20`。经用户明确允许后，仅在本机审计副本点击隐私页同意，用公开学校列表导出 3,570 条原始记录；没有登录学校账号，也没有读取任何用户课表。
本项目只根据可观察的学校名称、公开入口和系统标识独立实现适配器；没有抓取账号、Cookie 或用户数据，也没有复制第三方私有实现。

APK 中仍有依赖远端插件的适配路径，因此静态 APK 只能帮助确认分类和字段，不能替代真实学校验证。后续适配应由本校用户在自己的账号下完成并提交脱敏结构，不共享账号、Cookie 或完整课表响应。

## 新增或确认学校

1. 从学校官方渠道确认入口、认证域名、教务类型和完整学期课表页面。
2. 先使用通用类型验证；结构相同则只需新增经过核实的学校配置，不复制 Activity 或解析器。
3. 结构不同时，提交最小脱敏 HTML/JSON 字段样例和对应单元测试。
4. 核对连续周、断续周、单双周、同课多个时间段、教师、教室，以及不同培养层次/校区。
5. 真机登录、读取和预览全部通过后，才把该学校从“试用”改为“已验证”。

第一期核验脚本与证据报告位于 `analysis/school-adapter-v2-20260909/`。本次逐条扫描五大家族的 578 个 `adapter_required` 条目，没有条目同时满足学校官方公开来源、明确教务入口和可识别家族特征，因此没有自动提升状态。
