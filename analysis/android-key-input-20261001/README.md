# Android AI Key 输入与异常提示修复

## 原因与修复

使用者反馈复制的 Key 混入 `U+0001`，HTTP 客户端在设置 Authorization 请求头时抛出异常。原版直接展示底层异常信息，可能将完整凭据显示在失败弹窗中。本记录不保存反馈截图或真实凭据。

- 输入、保存、读取和发起请求共用 Key 检查：仅清理首尾的空白、控制字符和 Unicode 格式字符；中间出现空格、控制字符或非 ASCII 字符则报错，不保存也不发起请求。
- 保存成功后，输入框显示清理后的值；已保存的旧凭据在回填时同样检查。
- HTTP 客户端的未知异常只显示固定安全提示，不保留原异常消息和原因；界面层也对未知异常使用安全提示。
- AI 诊断继续仅记录结构、数量和状态，不包含凭据或底层请求头。

## 验证

- JVM 回归覆盖首尾复制杂字符清理、中间非法字符在建连前拦截、客户端异常不会回显凭据、不进行格式重试，以及诊断不含凭据。
- 原生测试覆盖非法保存不覆盖已有凭据、输入框提示、首尾控制字符清理、分服务商保存和回填。
- `testDebugUnitTest`：139 项通过；Debug / 测试 APK 构建、Lint 通过；Android 15 / API 35 的 AndroidJUnitRunner 结果为 `OK (2 tests)`。
- APK 凭据文件和 Key 特征检查均未发现匹配。
- 仅使用测试凭据和模拟返回，未调用真实模型。
